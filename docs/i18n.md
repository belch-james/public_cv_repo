# Internationalization (i18n) Guide

This project uses [i18next](https://www.i18next.com/) with [react-i18next](https://react.i18next.com/) for internationalization.

## Architecture

### File Structure

```
lib/
  i18n.ts           # i18n configuration and initialization
  I18nProvider.tsx  # React provider wrapper

public/locales/
  en/
    common.json     # English translations (default)
  fr/
    common.json     # French translations

components/typography/
  AppText.tsx       # i18n-aware typography component
```

### Configuration

The i18n system is configured in `lib/i18n.ts` with the following settings:

- **Default language**: `en` (English)
- **Fallback language**: `en`
- **Default namespace**: `common`
- **Detection**: Browser language detection enabled

## Translation Key Naming Convention

Keys follow a hierarchical dot-notation pattern:

```
{domain}.{surface}.{intent}[.{detail}]
```

### Domains

| Domain | Description |
|--------|-------------|
| `meta` | Site metadata (title, description) |
| `nav` | Navigation links |
| `footer` | Footer content |
| `landing` | Landing page sections |
| `projects` | Project cards and content |
| `caseStudy` | Case study content |
| `techStack` | Tech stack section |
| `workingStyle` | Working style items |
| `contact` | Contact section |
| `cv` | CV page content |
| `labels` | Reusable labels |
| `actions` | Button/action text |
| `errors` | Error messages |
| `aria` | Accessibility labels |

### Examples

```json
{
  "landing.sections.projects.title": "Featured Projects",
  "cv.sections.technicalSkills": "Technical Skills",
  "actions.viewCv": "View CV",
  "errors.downloadFailed": "Unable to download CV. Please try again."
}
```

## Usage

### In React Components

```tsx
import { useTranslation } from "react-i18next";

function MyComponent() {
  const { t } = useTranslation();

  return (
    <Typography>{t("landing.sections.projects.title")}</Typography>
  );
}
```

### With Interpolation

```tsx
// Translation: "Welcome, {{name}}!"
t("greeting", { name: "James" })
```

### With Fallback

```tsx
// Returns the key as fallback if not found
t("techStack.categories.frontend", "Frontend")
```

### Using AppText Component

The `AppText` component integrates typography with i18n:

```tsx
import { AppText } from "@components/typography";

<AppText
  variant="heading"
  i18nKey="landing.sections.projects.title"
  defaultText="Featured Projects"
/>
```

## Adding New Translations

1. Add the key to `public/locales/en/common.json`
2. Add the French translation to `public/locales/fr/common.json`
3. Use the key in your component with `t("your.key")`

## Adding a New Language

1. Create a new directory under `public/locales/` (e.g., `de/`)
2. Copy `en/common.json` to the new directory
3. Translate all values
4. The language will be auto-detected based on browser settings

## Server Components

Server components cannot use the `useTranslation` hook directly. For pages with server-side metadata, use a client wrapper:

```tsx
// page.tsx (server component)
export const metadata = { title: "My Page" };
export default function Page() {
  return <PageClient />;
}

// PageClient.tsx (client component)
"use client";
import { useTranslation } from "react-i18next";

export function PageClient() {
  const { t } = useTranslation();
  return <div>{t("my.key")}</div>;
}
```

## Best Practices

1. **Never hardcode user-facing text** - Always use translation keys
2. **Use semantic keys** - Keys should describe the content's purpose, not its value
3. **Group related keys** - Use the domain hierarchy consistently
4. **Provide fallbacks** - Use the second argument for fallback text
5. **Keep translations in sync** - Update all language files when adding new keys
